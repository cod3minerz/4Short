# Provider routing and benchmark policy

## Решение

4Short не привязывает продуктовую логику к одному AI-провайдеру. Российский control plane и
Timeweb S3 остаются источником истины, а наружу передаётся только минимальный артефакт конкретного
этапа: audio для STT или фрагменты транскрипта для поиска моментов.

## Production policy

1. Модель и endpoint должны находиться в явном allowlist.
2. `openrouter/auto` запрещён: он не гарантирует выбранную модель.
3. OpenAI и Anthropic исключены политикой продукта.
4. Для OpenRouter обязательны ZDR и запрет data collection.
5. Никаких fallback на модель вне allowlist.
6. Provider/model, latency, токены, ошибки и стоимость сохраняются на каждый job.
7. При росте error rate роутер отключает provider через конфигурацию, а не меняет бизнес-логику.

## Два прохода LLM

- Candidate model: дешёвая быстрая модель, которая работает по перекрывающимся блокам.
- Rerank model: более сильная модель, которая получает только кандидатов, удаляет повторы и
  обеспечивает разнообразие.

Стартовая конфигурация для benchmark:

- candidate: `deepseek/deepseek-v4-flash`;
- rerank: `deepseek/deepseek-v4-pro`;
- запасной контур: YandexGPT, если он выигрывает на русской речи по итоговому score/cost.

Эти названия являются конфигурацией, а не частью schema или EDL.

## STT benchmark

Корпус должен содержать не менее 20 часов с разрешением на тестирование:

- студийный и удалённый подкаст;
- один, два и четыре спикера;
- перебивания;
- русский с английскими терминами;
- тихий звук, шум, музыка;
- имена, бренды и профессиональный словарь.

Считаются:

- WER и entity WER;
- ошибка границ слов;
- DER для спикеров;
- доля отсутствующих таймкодов;
- p50/p90 времени;
- ₽/час;
- частота provider errors.

Побеждает не самая дешёвая модель, а минимальный `cost per accepted clip`: цена inference плюс
стоимость ручных исправлений и потерянных хороших моментов.

## LLM benchmark

Каждой модели даётся один и тот же закрытый набор транскриптов. Редактор вслепую оценивает:

- самостоятельность фрагмента;
- законченность мысли;
- точность границ;
- отсутствие дублей;
- разнообразие;
- соответствие пользовательскому запросу;
- корректность JSON.

Production допускает модель только при отсутствии регрессии относительно baseline и после
проверки цены на реальном распределении длины транскриптов.
