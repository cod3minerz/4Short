# Narezai production foundation

## Контуры и текущие подтверждённые решения

- Vercel обслуживает Next.js: публичная главная на `/`, рабочее приложение на `/dashboard`.
  Это предполагаемый вариант одного проекта; перед DNS-переключением нужно подтвердить домены
  и deployment в фактическом проекте Vercel.
- `api.narezai.com` — публичная HTTPS-точка control API на существующем сервере Timeweb.
  Сервер общий с CryoDoc/FunPay Cloud; его Caddy и текущие проекты нельзя перезапускать или
  менять без проверки изолированного Narezai-контура.
- `narezai` — отдельная база в Timeweb Managed PostgreSQL, роль приложения — `narezai_app`.
  Endpoint `managed-652579-9035109` доступен только внутри приватной сети Timeweb; не включать
  публичный IPv4 ради подключения. API должен использовать `verify-full` и сертификат,
  закреплённый в `infra/certs/timeweb-creodock-postgres.crt`.
  На существующем сервере подключение `psql` с `verify-full` подтверждено; grants `CONNECT`,
  `CREATE` на БД и `USAGE/CREATE` на `public` есть только для `narezai`, у роли нет `CONNECT`
  к `creodock`. Секрет установлен в `/etc/4short/database.env` (`root:root`, `0600`). Миграции
  не запускались: в БД уже 59 таблиц и 23 migration records против 13 записей в текущем checkout;
  первые 11 migration hashes совпадают, следующие 12 расходятся с checkout migrations 0011/0012.
  Все 59 таблиц и 4 sequence принадлежат `narezai_app`. Checkout journal говорит `dialect: sqlite`,
  а config — PostgreSQL. Сначала нужно согласовать историю и схему с конкретным reviewed release.
- `narezai-s3` — приватный Timeweb S3 bucket (`https://s3.twcstorage.ru`, region `ru-1`).
  Пользователь `narezai-app` имеет доступ только к этому бакету и custom object policy на
  `raw/`, `proxy/`, `derived/`, `assets/`. Ключи установлены в отдельный root-owned env-файл
  `/etc/4short/s3.env` на общем сервере; значения не сохраняются в Git/CI. Серверный smoke check
  подтвердил PUT/HEAD/GET/DELETE временного тестового объекта и multipart upload/list/abort в
  разрешённом prefix. Browser CORS и интеграция с приложением ещё не проверены; сервисы не
  развёрнуты.
- PostgreSQL — источник истины для аккаунтов, проектов, ledger, jobs и очереди.
- GPU/media worker — отдельный контур обработки. Immers.cloud/OpenStack подключение, GPU
  provisioning/autostop и подтверждённая обработка пока не завершены; не считать compose worker
  на общем control-сервере GPU-решением.
- Постоянные пользовательские объекты лежат в приватном S3. Локальный scratch на worker
  ограничен и удаляется после завершения/отмены задания.

## Провайдеры inference и данные

STT в текущей реализации выполняется `faster-whisper` локально на media worker, не на control
API. Выбранная production-модель и её ресурсная стоимость должны быть подтверждены на GPU
провайдере; текущие CPU-настройки — baseline, не обещание пропускной способности.

LLM для поиска моментов вызывается только через явно настроенный разрешённый адаптер. До
проверки ключей, доступности из production-региона, стоимости и согласия пользователей нельзя
объявлять семантический выбор моментов доступным. Без LLM доступны только фактически реализованные
режимы, а не имитация «лучших моментов».

Транскрипты могут содержать персональные данные. Передача текста внешнему провайдеру требует
allowlist, минимизации передаваемых фрагментов, учёта расходов и пользовательского согласия.

## Надёжность команд и очереди

Каждая изменяющая команда должна иметь идемпотентный контракт. Media job использует lease,
heartbeat и fencing token; поздний worker не должен публиковать результат новой попытки.
Недостаток ресурсов означает ожидание очереди, а не расход retry-бюджета. Очередь хранит
метаданные и ссылки на артефакты, а не видео или модели в памяти.

Перед включением внешнего worker должны быть проверены остановка native-процесса на отмене,
потеря lease, restart API/worker и безопасное восстановление после неполной загрузки артефактов.

## Timeweb PostgreSQL и S3

- `DATABASE_URL` указывает на базу `narezai` и роль `narezai_app` по приватному endpoint.
- `DATABASE_SSL=verify-full`; в образ API включён публичный сертификат для точного имени
  Managed PostgreSQL. Его отпечаток проверен: `E4:F6:09:39:A0:81:45:A8:0D:A6:CA:4D:2B:47:9F:82:AF:72:5D:3D:9C:B7:E8:ED:A7:8D:6C:B7:52:43:CC:9E`.
  Сертификат публичный, пароль/ключи в репозитории не хранятся.
- Миграции используют `public.__drizzle_migrations`. По согласованной схеме один выделенный
  пользователь `narezai_app` обслуживает API и запускает миграции; требуемые ему DDL права
  должны быть подтверждены текущими grants, не предполагать их по успешному подключению.
- Существующий bucket `narezai-s3` подтверждён приватным. Ограниченный object identity настроен
  и сохранён на сервере; не считать S3-путь рабочим до серверной проверки подписанных операций.
- Не хранить email и исходные имена файлов в object keys. Разделять исходники и результаты
  префиксами `raw/`, `proxy/`, `derived/`, `assets/`.
- Внешние действия S3 не выполняются внутри долгих PostgreSQL-транзакций. Для незавершённых
  multipart-сессий требуется cleanup/lifecycle и reconciler, который освобождает резервы.

## Render и публикация

- Единственный редактируемый источник — ClipDocumentV2; renderer получает неизменяемый snapshot
  и ResolvedRenderPlan. Это требование проверяется preview/render parity gate.
- Renderer не запускает модели и не принимает редакторских решений.
- Результат считается готовым только после проверки артефакта; хранить видео, субтитры,
  постер и QC-отчёт. ZIP не повторяет обработку.
- Capability flags остаются закрыты до прохождения относящихся к ним серверных HVE gates.

## Не считать готовым

На момент последней инвентаризации Narezai не развёрнут: защищённые DB- и S3-конфигурации уже
установлены на общем хосте, но нет deployment, API env, Caddy route или изолированной Docker
edge-сети. API DNS указывает на общий сервер, но это не означает, что endpoint обслуживается.
  S3 credentials установлены, и базовые server-side object/multipart операции проверены на
  временном fixture; browser CORS и интеграция не проверены. Наличие compose worker не означает
  GPU-подключение.

До серверных проверок нельзя заявлять production readiness, полный цикл, throughput, качество,
экономику на ролик или допустимое число параллельных клиентов. Все такие значения остаются
неизвестными до измерений на выбранном сервере и GPU provider.
