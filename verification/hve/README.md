# HVE verification assets

This directory contains public manifests, thresholds and synthetic recipes only. Real media, licenses, identity data, holdout annotations and signed URLs belong in a private Timeweb S3 bucket.

Lint the checked-in scaffold without claiming readiness:

```bash
npm run hve:manifest:lint
```

Strict validation intentionally fails until real licensed objects and annotations replace the scaffold:

```bash
npm run hve:corpus:verify
```

For a `ready` manifest, strict verification also requires an Ed25519-signed
object index generated by an **evaluator-only** S3 reader. It streams and
hashes the source, annotation and licence artifacts rather than trusting S3
metadata. The signing private key stays with the evaluator; the verifier uses
only its public key:

```bash
# Evaluator role only. Uses HVE_CORPUS_S3_* plus
# HVE_CORPUS_INDEX_SIGNING_PRIVATE_KEY. The ready corpus must not be the
# checked-in scaffold manifest.
npm run hve:corpus:index -- --manifest=/secure/hve/development-v1.json --out=/secure/run/development-index.json

HVE_CORPUS_OBJECT_INDEX=/secure/run/development-index.json \
HVE_CORPUS_INDEX_PUBLIC_KEY_FILE=/etc/4short/hve-evaluator-public.pem \
npm run hve:corpus:verify -- /secure/hve/development-v1.json
```

The index is intentionally written with mode `0600`; it contains private S3
object names and must not be committed. An unsigned index, a mismatched
manifest hash, an invalid signature, or a missing evaluator public key cannot
produce a corpus pass.

## HVE-G5 active-speaker evidence

The general layout corpus may omit speaker labels. A corpus item used for the
active-speaker gate must additionally contain the optional `activeSpeaker`
annotation block. It has an adjudicated `clean_two_person` or `panel_hard`
stratum and non-overlapping half-open turns with a semantic `speakerId` and an
optional semantic `faceRegionId`. `null` means the adjudicator verified that
the active speaker is off screen. Overlapping or ambiguous speech is left
unlabelled; it is never silently converted into a chosen speaker.

The evaluator owns both label and prediction bundles. They bind the raw
manifest bytes, signed object index, annotation hash and evaluator key
fingerprint. Candidate track IDs are mapped to semantic labels only within the
evaluator bundle, so an implementation cannot make a result look correct by
renaming detector tracks. The bundles are signed by the evaluator key before a
benchmark can be generated:

```bash
# Evaluator role only. These inputs contain private labels or model results.
npm run hve:sign:evaluator-bundle -- \
  --in=/secure/run/active-speaker-labels.unsigned.json \
  --out=/secure/run/active-speaker-labels.signed.json \
  --private-key=/etc/4short/hve-evaluator-private.pem

npm run hve:sign:evaluator-bundle -- \
  --in=/secure/run/active-speaker-predictions.unsigned.json \
  --out=/secure/run/active-speaker-predictions.signed.json \
  --private-key=/etc/4short/hve-evaluator-private.pem

npm run hve:evaluate:active-speaker -- \
  --manifest=/secure/hve/active-speaker-development-v1.json \
  --object-index=/secure/run/development-index.json \
  --public-key=/etc/4short/hve-evaluator-public.pem \
  --labels=/secure/run/active-speaker-labels.signed.json \
  --predictions=/secure/run/active-speaker-predictions.signed.json \
  --out=/secure/run/active-speaker-benchmark.json

npm run hve:verify:active-speaker -- \
  --report=/secure/run/active-speaker-benchmark.json
```

Promotion requires at least 24 independently sourced items and 120 adjudicated
turns in **each** stratum, as well as the frozen quality, safety and resource
thresholds. A two-item CLI smoke can prove the evaluator contract, but returns
`INSUFFICIENT` from the promotion verifier by design.

`npm run hve:smoke:g5` invokes this evaluator automatically only when all five
private inputs are supplied through `HVE_G5_CORPUS_MANIFEST`,
`HVE_CORPUS_OBJECT_INDEX`, `HVE_CORPUS_INDEX_PUBLIC_KEY_FILE`,
`HVE_G5_ACTIVE_SPEAKER_LABELS` and `HVE_G5_ACTIVE_SPEAKER_PREDICTIONS`. It
otherwise remains `INSUFFICIENT`; a self-reported benchmark path does not
exist.

While creating the index, the evaluator parses every annotation under the
strict HVE v1 contract, checks the item and licence binding, validates
half-open microsecond ranges, and requires every manifest evaluation range to
be covered by ground truth. A hashed but malformed annotation therefore cannot
become quality evidence.

Create the evaluator key pair once on the evaluator host (not in the app or
worker environment), then store only the public key where release verification
can read it:

```bash
umask 077
openssl genpkey -algorithm ED25519 -out /etc/4short/hve-evaluator-private.pem
openssl pkey -in /etc/4short/hve-evaluator-private.pem -pubout \
  -out /etc/4short/hve-evaluator-public.pem
```

`HVE_CORPUS_INDEX_SIGNING_PRIVATE_KEY` may point to the private PEM contents
through the evaluator secret manager. It must never be added to `.env`, Docker
Compose, GitHub Actions, the control API or the media-worker environment.

The smoke manifest is intentionally marked `status: scaffold`. A release verifier may accept only `status: ready`, non-placeholder hashes, all required splits/suites/strata, a real Timeweb baseline and every report listed in `production-v1.json`. Structural lint is never a quality or release PASS.

## HVE-G6 layout-director evidence

Automatic screen/presenter, gameplay/facecam and three/four-person panel
direction is a separate evaluator-only capability. It is **not** unlocked by
the executable, user-selected HVE-G6 compositor routes. A corpus range used
for this evaluation must contain `constraints.regionRoles`, mapping its
semantic `mustKeepRegionIds` to `screen`, `gameplay`, `face` or `facecam`.
This makes preservation measurable: a model track ID is never treated as a
ground-truth semantic region merely because it has a similar name.

The labels define the permitted/forbidden layout for each range; predictions
bind candidate region IDs to evaluator-owned semantic labels and record the
exact detector/director model hashes, target hardware and each visible-area
ratio. Labels, predictions and the final benchmark report are all Ed25519
signed by the evaluator. The private key stays only in the evaluator
environment; the promotion verifier receives only the public key.

```bash
# Evaluator role only: these two bundles contain private annotations and
# candidate mappings. They must be signed before scoring.
npm run hve:sign:evaluator-bundle -- \
  --in=/secure/run/layout-labels.unsigned.json \
  --out=/secure/run/layout-labels.signed.json \
  --private-key=/etc/4short/hve-evaluator-private.pem

npm run hve:sign:evaluator-bundle -- \
  --in=/secure/run/layout-predictions.unsigned.json \
  --out=/secure/run/layout-predictions.signed.json \
  --private-key=/etc/4short/hve-evaluator-private.pem

# Evaluator role only. This re-verifies every signed input and signs the
# derived report; it never accepts a hand-entered metric summary.
npm run hve:evaluate:layout-director -- \
  --manifest=/secure/hve/layout-development-v1.json \
  --object-index=/secure/run/layout-development-index.json \
  --public-key=/etc/4short/hve-evaluator-public.pem \
  --private-key=/etc/4short/hve-evaluator-private.pem \
  --labels=/secure/run/layout-labels.signed.json \
  --predictions=/secure/run/layout-predictions.signed.json \
  --out=/secure/run/layout-director-benchmark.signed.json

# Promotion-verifier role: public key only.
npm run hve:verify:layout-director -- \
  --report=/secure/run/layout-director-benchmark.signed.json \
  --public-key=/etc/4short/hve-evaluator-public.pem
```

`npm run hve:smoke:g6` invokes the evaluator and then the promotion verifier
only when all six evaluator-only inputs are present:
`HVE_G6_CORPUS_MANIFEST`, `HVE_CORPUS_OBJECT_INDEX`,
`HVE_CORPUS_INDEX_PUBLIC_KEY_FILE`, `HVE_G6_LAYOUT_LABELS`,
`HVE_G6_LAYOUT_PREDICTIONS` and `HVE_G6_EVALUATOR_PRIVATE_KEY_FILE`. The
normal application, media-worker and CI environment must not receive the last
secret; their smoke result is deliberately `INSUFFICIENT` rather than a
self-reported pass.

Promotion requires at least 24 independently sourced items and 120
independently labelled ranges in **each** screen-presenter, gameplay-facecam
and three/four-person-panel stratum. It also requires the frozen recall,
layout, no-forbidden-layout, preservation, transition latency and no-swap
limits. A report without a valid evaluator signature is a hard `FAIL`; missing
evidence is `INSUFFICIENT`. HVE-G6 remains scaffolded until a target Timeweb
run supplies this real evidence.

## Sealed production release evidence

`npm run hve:verify:release` is the final fail-closed HVE-G9 verifier. It is
not a command for CI smoke output or for an application/worker secret. The
release evaluator signs one `release-evidence.json` after it has run the
immutable candidate image against the sealed corpus. That signature binds the
candidate's full Git SHA, OCI digest, corpus facts, aggregate metrics,
baseline comparison and SHA-256 of every report artifact. The verifier then
checks the files again rather than trusting a JSON summary.

In particular, `metrics.json.aggregateMetrics` and `corpus-summary.json` must
be byte-bound artifacts that exactly match the signed metrics and corpus claims
inside `release-evidence.json`; a signature over a separate, unaudited summary
is not enough.

The aggregate release metrics also include the blinded market-study criteria:
HVE preference rate, its lower 95% Wilson bound, count of materially losing
strata and manual-correction rate. A suite named `market` without those values
is `INSUFFICIENT`; a value outside the frozen limit is `FAIL`.

The evaluator/public-key boundary is intentional:

```bash
# Evaluator role only. This key is never present in application, worker or CI
# environments. The report directory is private as it contains corpus facts.
HVE_RELEASE_EVALUATOR_PRIVATE_KEY_FILE=/etc/4short/hve-evaluator-private.pem \
npm run hve:assemble:release -- \
  --evidence-dir=/secure/release-candidates/2026-08-03 \
  --candidate-git-sha=<40-char-immutable-sha> \
  --candidate-image-digest=sha256:<immutable-oci-digest>

# Release-verifier environment: evaluator public key only.
npm run hve:verify:release -- \
  --evidence-dir=/secure/release-candidates/2026-08-03 \
  --thresholds=/secure/hve/production-v1.frozen.json \
  --public-key=/etc/4short/hve-evaluator-public.pem
```

For an evaluator dry run before threshold freeze, append `--allow-scaffold` to
the assembler command. That envelope is deliberately rejected by the verifier
with `INSUFFICIENT`. This flag belongs to the evidence assembler only: corpus
validation has a separate `--manifest-lint` mode for checking the schema of the
checked-in synthetic scaffold. It prints `HVE MANIFEST LINT ONLY` and cannot
verify objects, enable a capability or approve a release.

It returns `0` only for a frozen, active threshold file and a complete signed
pass. `2` means evidence is absent, under-sampled or explicitly insufficient;
it must never be treated as approval. `1` means a signed fact, artifact hash,
candidate identity, corpus assertion or quality result failed. The current
checked-in `production-v1.json` stays `scaffold`, so it deliberately returns
`2` until corpus calibration and an independent threshold freeze happen.

The release evidence schema is
`verification/hve/schemas/release-evidence.schema.json`. Do not store the
private evaluator key, sealed labels, raw report media or signed evidence in
Git, Compose, the control API, or a worker container.

The complete role separation, target-worker benchmark, corpus, signing and
staged rollout procedure is [hve-sealed-release.md](../../docs/operations/hve-sealed-release.md).

Rules:

- one immutable prefix per corpus version;
- every source and annotation object key is unique within a corpus manifest;
- every object has SHA-256 and license reference;
- time ranges are half-open integer microseconds, sorted and non-overlapping;
- no production customer media is added automatically;
- holdout annotations are inaccessible to the implementation environment;
- thresholds and hardware baselines are reviewed separately from engine changes.
- `status: scaffold`, missing suites, missing objects or missing metrics always result in `INSUFFICIENT`, never `PASS`.
- exceptions use the time-bounded `schemas/waiver.schema.json`; a waiver cannot convert missing evidence into PASS and cannot waive billing, security, full-decode or data-integrity failures.
